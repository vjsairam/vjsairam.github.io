What this report can't see

  • GPU utilisation. Requests show what pods reserved, not how busy the GPUs are. Only nvidia.com/gpu and amd.com/gpu are counted. With one namespace read, requests from other namespaces aren't counted, so spare GPUs aren't reported.
  • First starts. Pod status keeps only the latest Ready transition, so a pod whose readiness dropped and came back looks slower than it started, and a restarted pod's first start is gone.
  • Settings outside the pod spec. vLLM flags set inside a shell script or a config file aren't parsed, and only one serving container per pod is checked.
  • Network reachability. Exposure findings come from Service settings; nothing was probed.
  • Older starts. Kubernetes keeps events for about an hour by default, so image pull times for older pods are usually gone.
